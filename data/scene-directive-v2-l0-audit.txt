# SceneDirective V2 — L0 Audit
# Branch: feature/scene-directive-v2
# Date: 2026-07-30
# Scope: code path verification only (no model calls)

NOTE: Repo already has Living Scene Directive ("Continuity Director") gated by
LIVING_SCENE_DIRECTIVE_V2_ENABLED. This audit covers legacy V1 (sceneDirective.ts)
plus that living path. Event-Restraint V2 (SCENE_DIRECTIVE_V2_MODE) is the new work.

================================================================================
1. SceneDirective가 매 요청 생성되는가
================================================================================
확정 사실:
  chat route는 매 요청마다 buildSceneDirective(...)를 호출한다.
  Living canary ON이면 추가로 buildLivingSceneDirective(...)를 호출한다.
파일과 함수:
  src/app/api/chat/route.ts — request assembly (~1099-1130)
  src/lib/sceneDirective.ts — buildSceneDirective
  src/lib/livingSceneDirective.ts — buildLivingSceneDirective
관련 코드:
  const legacySceneDirective = buildSceneDirective({ ... });
  const livingSceneDirective = livingSceneDirectiveOn ? buildLivingSceneDirective(...) : null;
잠재 영향:
  매 턴 지시문이 항상 조립되므로 BASE_SCENE_ENGINE_RULE의 "무언가 움직이라" 압력이
  평온한 장면에도 반복 주입된다.
확신도: CONFIRMED

================================================================================
2. SceneDirective가 매 요청 prompt에 주입되는가
================================================================================
확정 사실:
  sceneDirectiveBlock이 contextBuilder로 전달되고 pushSceneDirective()로 주입된다.
  Living ON이면 living render, 아니면 legacy render.
파일과 함수:
  src/app/api/chat/route.ts (~1128-1130, ~1270)
  src/services/contextBuilder.ts — pushSceneDirective (~796-801, ~917-924)
관련 코드:
  sceneDirectiveBlock = living ? renderLiving... : renderSceneDirectiveForPrompt(legacy)
잠재 영향:
  빈 블록 억제는 trim 여부만; 정상 경로에서는 거의 항상 비어 있지 않다.
확신도: CONFIRMED

================================================================================
3. intensity 0에서도 BASE_SCENE_ENGINE_RULE이 사건 진행을 요구하는가
================================================================================
확정 사실:
  BASE_SCENE_ENGINE_RULE은 intensity와 무관하게 매 render에 붙는다.
  문구: "관계, 단서, 환경, NPC, 세계 반응, 생활 변수, 이전 선택의 결과 중 하나를
  조용히 움직인다."
파일과 함수:
  src/lib/sceneDirective.ts — BASE_SCENE_ENGINE_RULE, renderSceneDirectiveForPrompt
관련 코드:
  lines ~61-65, ~265-285
잠재 영향:
  intensity=0(rest)에서도 "사건을 만들라"는 엔진 압력이 남는다.
  Living path는 PRIVATE_SCENE_CONTINUITY_RULE로 완화하지만 별도 canary다.
확신도: CONFIRMED

파일과 함수:

잠재 영향:
  평온·무표식 장면도 항상 전개 방향이 채워져 "새 사건 없음" 경로가 없다.
확신도: CONFIRMED

5. 작전 키워드가 npc_action을 자동 추가하는가
================================================================================
확정 사실:

잠재 영향:
  lorebook/memory에 작전 단어만 있어도 NPC 행동이 선택될 수 있다
  (아래 6번과 결합).
확신도: CONFIRMED

6. memory/relationship/lorebook이 현재 progression type 선택에 쓰이는가
================================================================================
확정 사실 (V1):
  buildSceneDirective는 memoryText + relationshipMemoryText + lorebookText를
  recent messages / current user message와 하나의 text로 합쳐 selectProgressionTypes에 넣는다.
파일과 함수:
  src/lib/sceneDirective.ts — buildSceneDirective (~238-245)
관련 코드:
  const text = [compactText(...), currentUserMessage, memoryText, relationshipMemoryText, lorebookText].join("\n");
잠재 영향:
  침실 휴식 중에도 lorebook의 "임무/전투/NPC"로 operation/npc_action이 선택될 수 있다.
Living path (INFERRED/CONFIRMED mix):
  livingSceneDirective는 분류에 memory/lore를 쓰지 않는다고 주석/구현상 명시
  (Grounded pools only). CONFIRMED for living classification separation.
확신도: CONFIRMED (V1); CONFIRMED (Living does not classify from memory/lore)

잠재 영향:

확신도: CONFIRMED

8. trigger 우선순위가 하드 배타인지 텍스트 지시뿐인지

잠재 영향:
  모델이 두 번째 사건을 추가할 여지가 남는다 (소프트 지시).
확신도: CONFIRMED

10. scene presence 데이터가 일반 채팅에서 실제 신뢰 가능한지
================================================================================
확정 사실:
  observer bootstrap / presence writes / sceneEvidence persist는
  Persona Secret Discovery kill-switch가 OFF(기본)이면 no-op이다.
  sceneDirective / livingSceneDirective는 presence를 읽지 않는다.
파일과 함수:
  observerBootstrap.ts; scenePresenceActions.ts; personaSecretBoundaryPolicy.ts
  sceneEvidence extract paths
관련 코드:
  isPersonaSecretDiscoveryEnabled unset → false
잠재 영향:
  재수렴 SLA용 authoritative separation state로 presence를 재사용할 수 없다.
  Event-Restraint V2는 별도 persistence가 필요하다.
확신도: CONFIRMED

================================================================================
Additional confirmed V1 pressure points
================================================================================
- detectSceneStagnation: short user replies (<=12 chars) + low movementTerms
  짧은 새 행동("문을 연다")도 shortUserReplies로 정체 쪽으로 기울 수 있음. CONFIRMED
- selectSceneIntensity returns max 4; type allows 5 but unused. CONFIRMED
- renderIntensity may emit "1~2" / "2~3" ranges when stagnant. CONFIRMED
- buildNextBeatHint defaults to external pressure / clue / daily_life relationship
  temperature / environment change phrases. CONFIRMED
- Intensity 5 reserved in type but never selected — recommend drop to 0|1|2|3|4 in V2.

================================================================================
Intensity decision (for V2 implementation)
================================================================================
Choice: recommendedIntensity: 0 | 1 | 2 | 3 | 4
Reason: selectSceneIntensity never returns 5; range rendering hands discretion to the model.
Keep V1 type unchanged for regression safety; V2 uses exclusive 0-4 integers and
renderIntensityV2 emits a single integer.
