## 2. 전달 차단 경로 (성인 OFF Main RP, `effectiveAdultRp=false`)

- 검사 전 본문은 `createAdultOffOutputHold`가 보류한다. `delta`/`append`/`replace`와 `text`·`delta`·`content`·`finalContent`를 가진 모든 이벤트가 대상이다. `status`/`stream_heartbeat`/`turn_persisted` 같은 상태 안내는 그대로 통과해 기존 "마무리 중…" 안내가 유지된다.
- `fullText`·`streamVisibleTextRef`와 부분 저장·최종 저장은 승인 이후에만 대입된다. 800ms 부분 저장 타이머와 최종 저장은 승인 전 본문을 읽을 수 없다.
- 후보는 원문(`result.text`)과 스트림 표시본(`streamVisibleText`) 둘 다 검사한다.
- 차단(`adult_output_blocked`)·검사 실패(`adult_output_check_failed`: HTTP 오류, 시간 초과, 잘못된 출력)·공급자 응답 거절(`model_refusal`)은 서로 다른 `generationFailure` 원인으로 기록된다.
- 세 경우 모두 #1668의 공통 실패 경로(`failMainRpTurn`)로 합류한다: 본문 빈 문자열 저장, 공급자 실비 `failed_with_usage` 1행 유지, `requestedPoints:0`의 `waived` 정산 1회, 상태창·추천 입력 등 후속 유료 호출 없음, 자동 재시도 없음, 같은 `requestId` 재전송 시 공급자 호출 0회.

### #1668과의 적용 순서

#1668(a11da88c)이 이미 병합되어 있다. 이 변경은 그 위에 얹는다. #1668의 인라인 실패 블록을 `failMainRpTurn` 한 곳으로 옮기고(동작 동일), 거기에 사이트 차단 원인 두 개를 추가했다. 정산·환불 로직은 새로 만들지 않았고 같은 `settleChatTurnBillingExactlyOnce`를 쓴다. 따라서 이중 환불·차감 경로가 없다. 기존 `mainRpStrictFailure.test.ts`의 소스 고정 검사는 새 분기 이름으로 앵커만 갱신했다.

## 3. 검증 — 두 종류를 구분한다

### 3.1 합성 공급자 응답 + 분류기 스텁 (노출·저장·정산 경로)

`src/lib/adultOffOutputGuard.test.ts`(순수 로직 16건), `src/lib/adultOffOutputGuard.production.test.ts`(실제 `POST /api/chat` 핸들러 5건). 제한 판정은 본문 표식으로 결정하는 스텁이다.

- 차단·검사 실패 3종(HTTP 503, 비JSON, 모순 출력): SSE에 본문 이벤트 0건, 검사 중 DB 어시스턴트 행 본문 `""`, 최종 `""`, 메시지 API 본문 없음, 잔액 불변, `waived` 정산, `main-rp` 원장 1행 `failed_with_usage`, 상태창·추천 호출 0건, 분류기 호출 1회(재시도 없음), 같은 요청 재전송 시 공급자·분류기 호출 0회.
- 승인: 분류기 호출 시점에 DB 본문이 비어 있고, 승인 후 본문이 한 번 방출·저장·정상 차감된다.
- 공급자 거절은 분류기를 호출하지 않고 `model_refusal`을 유지한다. 검사 OFF는 분류기를 호출하지 않는다.

**이 검증은 분류 정확도를 증명하지 않는다.** 스텁은 표식 문자열만 본다.

- 전달 본문은 원문과 같은 내용이며 문단 구분만 달라진다(저장본이 26~96자 길다). 검사는 원문과 스트림 표시본을 대상으로 하며 이후 문단 서식 처리 결과는 재검사하지 않는다.
- 사용자에게는 분류기 완료 직후(1~2ms 이내) 본문이 한 번에 도착했다. 상태 안내와 heartbeat만 먼저 갔다.

### 미검증

- 수위 제한 수준의 장면을 실제 Main RP 모델에 요청하지 않았다. 네 모델이 제한 수준 본문을 쓸 때 분류기가 어떻게 판정하는지는 **미검증**이다.
- 네 호출은 모두 정상 로맨스이므로 실제 모델 출력에 대한 오탐 1회 표본(4/4 허용)만 있다. 미탐은 실측하지 못했다.

## 5. 남은 한계, 추가 비용, 지연

- **기본 OFF**: 활성화 전에는 보호가 없다. 보호 완료가 아니다.
- **스트리밍 상실**: 성인 OFF 방에서 사용자는 전체 생성이 끝나고 분류가 끝날 때까지(이번 실측 30~71초) 본문을 보지 못한다. 요구사항(먼저 스트리밍하고 나중에 지우는 방식 금지)에 따른 구조적 비용이다.
- **추가 지연**: 분류기 6.9~10.9초가 턴마다 직렬로 더해진다(공급자 생성 시간의 약 12~23%). 단일 36,000자 구간 기준이며 더 긴 본문은 구간 수만큼 직렬로 늘어난다.
- **추가 비용**: 분류 1회 약 0.3~0.4원(실측 $0.00021~$0.00032 = 0.29~0.43원, 구간 수에 비례). 성인 OFF Main RP 턴마다 상시 발생한다. 차단·검사 실패 턴은 사용자 0P이므로 공급자 실비와 분류 비용이 운영 부담으로 남는다.
- **원장 연결**: 분류기 호출은 `adult-off-output-moderation` 요청 종류로 `moderation` 원가 센터에 기록되지만 턴(`assistant_message_id`)에는 연결되지 않는다.
- **검사 범위 밖**: HTML 시각 카드·flash 전용 턴(`htmlFlashOnlyTurn`)은 Main RP 공급자 호출이 없어 이 검사 대상이 아니다. 성인 ON 방은 정책상 대상이 아니다.
- **낮은 확신 허용**: `decision=allow`는 확신이 낮아도 통과한다. 임계값을 두지 않았다.
- **승인 이후 서식 처리**: 문단 서식 단계는 승인된 본문에서 공백만 바꾸는 것으로 관측했지만 코드로 강제하지 않았다.
- **이전 감사 수치**: 635.11원/697.11원 견적은 재현하지 못했다. 현재 조건 재계산은 위 4절.
