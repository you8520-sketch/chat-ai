# FOLLOW-UP — Bonds 입력(`buildPart1Recap`) 최소 설계 제안 (이번 PR·후속 PR 모두 생성 입력 미변경)

> 상태: 과거 사건이 recap에서 빠진다는 점은 코드로 확인된 사실입니다. 그러나 비밀 오류의 직접 원인은 미확정이므로 이번 PR에서 생성 입력을 바꾸지 않고, 이 설계는 FOLLOW-UP으로 보존합니다.

## 현재 (main)

`src/lib/officialSupply/author.ts`의 `buildPart1Recap(half1)`은 Bonds(관계·비밀·`selfDrive`) 생성 호출(`character_bible_bonds`)에 아래만 전달합니다.

| 전달됨 | 전달되지 않음 |
| --- | --- |
| 이름 | `backstory.events[]`(사건·선택·현재 흔적) |
| `personality.behavioral` 앞 400자 | `values.fears` / `coreValues` / `nonNegotiable` |
| `values.desires` | `abilities[]`(범위·한계·대가) |
| `contradiction` 앞 160자 | `habits`, `dailyLife` |
| `situation.personalSituation` 앞 220자 | |

비밀(`secrets`)은 Bonds 단계에서 작성되고, 과거 사건(`backstory`)은 1부(part 1)에서 작성되므로, Bonds 작성자는 **과거 사건을 보지 못한 채** 비밀과 관계를 씁니다.

## 확인된 것과 확인되지 않은 것

- 확인됨: recap이 과거 사건과 핵심 가치를 충분히 전달하지 않는다(위 표, 코드 직접 확인).
- **확인되지 않음**: 이것이 볼프강 비밀 #1의 내부 모순이나 비밀 #2와 백스토리 #1의 불일치의 직접 원인이라는 증거는 없습니다(생성 로그·프롬프트 응답 재현은 하지 않았고, 유료 생성 비교도 하지 않았습니다). 원인 후보일 뿐입니다.

## 제안 (기존 recap 소유자 안에서만, 새 프롬프트·새 단계 없음)

`buildPart1Recap`의 기존 `.join("\n").slice(0, 1200)` 구조를 유지하고, 줄 하나만 추가합니다.

```
과거 핵심: <event 요약 ≤70자> → <choice ≤50자> → 지금: <residue ≤60자>   (사건 최대 3개, 줄바꿈 구분)
```

- 사건·선택·현재 영향만 전달하고, 배경 서술 전체·능력·습관은 전달하지 않습니다.
- 현재 최대 입력은 이름 + 400 + 160 + 220자에 욕망·라벨이 더해진 정도라 상한 1,200자 안에 약 300~400자 여유가 있습니다(욕망 길이에 따라 다름). 추가 줄은 이 여유 안에 들어가도록 사건 3개·항목별 글자 상한을 둡니다. 여유가 부족하면 기존 `slice(0, 1200)`이 맨 뒤(`현재 상황`)부터 잘리므로, 구현 시 줄 순서와 상한을 함께 확인합니다.
- 새 프롬프트 문장을 추가하지 않습니다. Bonds 프롬프트(`authorPrompts.ts`)의 기존 ‘이미 쓴 내용을 반복하지 말 것’ 규칙은 그대로 두고, 입력 데이터만 늘립니다.

## 검증 계획(구현 시)

1. 단위 테스트: 사건이 있는 1부 응답을 입력해 recap에 `과거 핵심` 줄이 3개 이하로, 1,200자 이하로 나오는지.
2. 오프라인 비교: 저장된 1부 응답(볼프강·루시안 pilot `bible`)으로 recap 문자열 before/after를 diff — 유료 생성은 하지 않습니다.
3. 유료 생성 A/B는 GPT·사용자 승인 후 별도 작업으로 분리합니다.
