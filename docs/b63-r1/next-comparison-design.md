# B63 R1 — 다음 유료 비교 설계안 (실행 금지)

이 문서는 설계만 제안한다. R1에서는 유료 호출을 0회 수행한다.

## 1. 층화

거리 구간 × 질문 유형의 3×3 셀.

| 거리 | 명시 회상 | 암묵 장면 단서 | 회상 불필요 대조 |
|---|---|---|---|
| RAW 내 (T97–100) | “T100에서 제이가 뭐라고 했나” | “방금 그 남자가 다시 나타나면?” | “지금 라운지 분위기를 이어서 묘사” |
| 최근 요약 (T75–94) | “T80 반지 역할” | “T80과 같은 격납고 냄새가 나면?” | “T80과 무관한 새 식사 장면” |
| 그 이전 (T1–74) | “T50에서 오스카가 요구한 것” | “T20의 ‘자산’ 호칭이 지금 대화에 스며들면?” | “T50과 무관한 날씨 잡담” |

- 각 셀 최소 2문항 → 18문항.
- arm은 **1턴 요약 vs 5턴 요약** 2개.
- 18 × 2 = 36회 + T101 자연 이어가기 2회 = **38 calls**.
- 같은 RAW(T97–100), 같은 총 memory char/token 예산, 같은 B62 공통 주입(또는 양쪽 제거), 같은 모델/temperature/maxTokens.

## 2. 판정 기준 (실행 전 확정)

각 응답에 대해:

1. **Grounded recall**: 원문 정답 + 입력 내 근거 위치(system/RAW/요약/B62/질문)를 모두 제출한 경우만 성공.
2. **No-evidence correct**: 정답과 일치해도 입력 근거가 없으면 회상 성공으로 집계하지 않는다.
3. **Unnecessary injection rate**: “회상 불필요 대조” 셀에서 검색/요약 블록이 주입되어 장면을 오염시킨 비율.
4. **False-answer rate**: 입력에 없는 질문에 단정한 비율.
5. **Token delta**: arm별 system/history/input token과 char.
6. **RP use**: 검색 결과가 존재함과 RP가 올바르게 사용함을 분리. RP 사용은 별도 rubric으로 GPT가 평가.

사전 합격선(예시, 실행 전 고정):
- Grounded recall이 5턴 arm 대비 1턴 arm에서 +2문항 이상.
- Unnecessary injection rate가 5턴 arm 대비 +10%p 이하.
- Input token 증가가 +15% 이하.
- False-answer rate가 악화되지 않음.

## 3. 최소 문항·호출·비용

- 18문항 × 2 arm = 36 calls.
- T101 자연 이어가기 2 calls.
- 합계 **38 calls**.
- B63 structured QA의 실제 단가($0.0035–0.0186/call)와 RP 단가($0.01–0.02/call)를 기준으로 **$0.4–$0.8 (약 550–1,100원)** 예상.
- 요약 생성이 필요하면 별도. 100턴 기존 요약을 재사용하면 0 calls.
- 500/1,000턴은 원문 자료가 없으므로 100턴 복제·턴 번호 변경으로 만들지 않는다. 별도 원문 확보 후 설계한다.

## 4. 실행 전 체크

- [ ] B62 공통 주입을 양쪽에서 제거하거나 양쪽에 동일하게 유지
- [ ] RAW4/RAW6을 양쪽 동일하게, final messages에서 실제 RAW 범위 확인
- [ ] T95–96 gap이 없는지 확인
- [ ] 1턴/5턴 요약의 총 char/token 예산 일치
- [ ] 정답표를 프롬프트에 넣지 않음
- [ ] 24개 응답 audit table의 evidence 위치를 자동 저장
- [ ] 비용 상한과 중단 조건을 실행 전에 기록

## 5. 하지 않는 것

- 500/1,000턴을 100턴 복제로 만들지 않는다.
- 새 모델·벡터 DB·그래프·병렬 memory owner를 추가하지 않는다.
- 특정 turn 번호/정답을 production 코드에 하드코딩하지 않는다.
